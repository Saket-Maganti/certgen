# CertGen Project Master Context — V4 Addendum

## V4 identity

V4 is the **CVPR-range upgrade pack** for CertGen. It is not a result pack. It is a broad infrastructure and paper-facing upgrade that prepares CertGen for real empirical execution and eventual CVPR submission quality.

## Starting point

Before V4:

- V1 built the repo scaffold and claim-safe smoke foundation.
- V2 added clean-core KID/MMD/CMMD streams, bounded confidence sequence scaffolds, optional-stopping smoke lab, and certificate API.
- V3 added real-pilot readiness: provenance ledger validator, real feature-cache contracts, dry-run extraction adapters, metric reproduction audit, first-pilot orchestrator, certificate replay, pilot report cards, registry/availability tables, and upgraded docs.

## V4 scientific purpose

V4 should make the project able to answer, once real data is supplied:

> Among reported generative-model wins, which are decided, undecided, blocked by provenance/reproduction issues, or ranking-unstable under optional-stopping-valid clean-core certificates?

## V4 technical scope

V4 adds:

- state intake and destructive audit;
- provenance-to-real-run planning;
- Kaggle/Colab/local feature extraction notebook generators;
- preprocessing locks;
- metric reproduction gates;
- batch certificates and multiple-comparison adjustment;
- dependence diagnostics;
- decidedness and ranking-stability audits;
- first-real-pilot controller;
- literature claim trace;
- paper figure/table/result-card generation;
- CVPR paper scaffold;
- reviewer attack harness;
- reproducibility capsule;
- release safety scanner;
- final V4 audit and handoff.

## What V4 must not do

V4 must not claim:

- a real undecided fraction;
- a real ranking movement;
- a real decided model comparison;
- a rigorous FID certificate;
- that any published paper is wrong;
- that smoke/synthetic outputs are evidence.

## Critical policies

### Clean-core metrics

Rigorous certificates remain centered on KID/MMD/CMMD-style estimators and streams.

### FID / FD-DINOv2

FID and FD-DINOv2 remain descriptive/reproduction/sensitivity metrics unless a mathematically valid certificate path is implemented and audited. V4 should reinforce this.

### Multiple comparisons

Any claim-level batch audit must account for multiple comparisons or clearly label unadjusted analysis as exploratory/non-claim.

### Provenance

No comparison can enter claim consideration unless released samples/checkpoints/features, license status, sample count, reference set, and preprocessing are verified.

### Reproducibility

Zero-cost reproducibility remains core. Kaggle/Colab notebooks may be generated, but tests must stay local and small.

## V4 success condition

V4 succeeds if a fresh agent can take the handoff and run:

1. validate one real provenance ledger;
2. generate/validate feature caches;
3. lock preprocessing;
4. reproduce a reported metric point estimate;
5. run clean-core certificates;
6. generate a decidedness/ranking-stability report;
7. keep all results non-claim until gates pass.

## V5 warning

After V4, do not keep building infrastructure indefinitely. The next pack should be real pilot execution unless a concrete real-run failure exposes a missing gate.

## Single most important V4 sentence

V4 turns CertGen into a CVPR-facing empirical audit machine, but it still refuses to claim anything until real provenance, feature, reproduction, and certificate gates pass.
