# Generator randomization and probability space

Status: prospective execution contract v1; no empirical evidence; `claim_allowed=false`.

## Objects and conditioning

The reference empirical population is the fixed, authenticated CIFAR-10 test manifest. The v2 draw plan samples from that population IID with replacement. Its SHA-256 and ordered draw IDs are precommitted before outcomes are inspected. The probability statement is ex ante over that declared reference-draw law; retaining the realized draw-plan file is a reproducibility device, not permission to redesign the plan.

The two generator checkpoints, revisions, source tree, configuration, sample-ID policy, seed derivation, and ordered seed manifest are fixed. A generator output is the deterministic result of checkpoint, revision, authenticated code, dependency lock, device/API semantics, and one frozen `torch.Generator.manual_seed` integer. The current master seed was prospectively fixed, not recorded as a draw from a probability distribution. Consequently the generator-seed “law” for the executed study is a Dirac measure on the frozen manifest. Hash-derived seeds must not be described as IID random draws merely because their bits look pseudorandom.

The confirmatory target implemented here is therefore conditional on the frozen generator manifests: at each frozen prefix it compares the finite, precommitted generated-output sets to expectations over the declared IID reference-draw design after the fixed feature map. It is not an unconditional claim about all future draws from a model's generative distribution. Any paper claim about a model distribution needs a new prospective contract that defines and justifies a genuine generator-randomization law.

## Stream and filtration

For a fixed extractor, revision, preprocessing hash, unit-sphere normalization, RBF gamma, and frozen pairing permutation, one stream unit contains disjoint A, B, and reference pairs. Its value is

`k(A1,A2) - k(B1,B2) - k(A1,R2) - k(A2,R1) + k(B1,R2) + k(B2,R1)`.

The common `k(R1,R2)` term cancels. With a `[0,1]` RBF kernel the contribution lies in `[-3,3]`. The filtration at time `t` is generated by the first `t` revealed contributions plus all frozen design objects. Checkpoints, seed manifest, reference sampling law, feature maps, kernel, pairing order, multiplicity allocation, prefix grid, and stopping rule must be fixed before the first contribution is inspected.

Conditional on the frozen generator outputs and design objects—but not on the unrealized reference draws—the reference pairs are independent under the declared with-replacement law. The bounded Hoeffding construction controls deviations of the running sum from the corresponding cumulative conditional-mean sequence. Conditional means may vary with the fixed A/B rows; the estimand at a prefix is their precommitted prefix average. Duplicate or adaptively selected generated rows, undeclared reference reuse, outcome-dependent ordering, cache selection, kernel tuning, or extractor changes invalidate this mapping and fail closed.

## Validity boundary

The canonical union-Hoeffding sequence is valid for the bounded conditional-mean stream just described, with Bonferroni allocation across the two confirmatory feature hypotheses. It is valid at optional stopping because every integer time is covered by the predeclared summable alpha allocation. This statement is conditional on authenticated implementation and the declared sampling assumptions; no real GPU execution has yet verified those inputs.

Validity is not conditional on a realized reference manifest in the probabilistic sense—conditioning on every realized random draw would remove the sampling randomness. It is conditional on the frozen generator manifest and is unconditional over the precommitted reference-draw randomization. Replay after the draw realizes the same calculation but does not change the ex-ante probability statement.

The deterministic seed schedule matches this finite-manifest target. It does not, by itself, support population-level generator expectations. That distinction is a scientific scope limitation, not an execution-transport defect, and all outputs remain `claim_allowed=false`.
