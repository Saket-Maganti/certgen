# CertGen Project Master Context — V5 Addendum

## V5 Direction

CertGen V5 is the **CVPR-ready-except-runs** upgrade.

The project is no longer merely a code scaffold. V1–V4 already built the core repository, clean-metric certificate scaffolds, feature-cache contracts, provenance ledger, real-run planner, notebook generator, preprocessing locks, batch certificates, multiple-comparison diagnostics, ranking/decidedness reports, first-real-pilot controller, literature tracing, paper artifact scaffolds, reviewer harness, reproducibility capsule, and release safety scan.

V5's role is to make CertGen paper-ready and release-ready **except for real execution**.

## V5 Main Objective

Create every structure needed for a CVPR submission:

- paper scaffold;
- supplement scaffold;
- analysis-plan lock;
- result contracts;
- claim trace;
- related-work board;
- proof obligations;
- reproducibility capsule;
- release/anonymity scan;
- reviewer response bank;
- CVPR readiness scorecard;
- final audit and handoff.

## V5 Evidence Boundary

V5 must preserve:

- no real evidence;
- no claim-eligible artifacts;
- no undecided-fraction claim;
- no ranking-movement claim;
- no compute-savings claim;
- no rigorous FID claim;
- no fake citations.

Expected V5 artifacts should usually be:

- `template_only`
- `dry_run_only`
- `pilot_candidate`

not `claim_eligible`.

## V5 Success State

After V5, the project should honestly say:

> CertGen is CVPR-ready-except-runs: codebase, paper scaffold, supplement scaffold, result contracts, claim gates, reproducibility capsule, and reviewer defenses exist. It is not submission-ready because real claim-eligible empirical runs have not been executed.

## Next Required Action After V5

Do not build V6 generic infrastructure.

The next action is:

1. populate one real provenance ledger;
2. validate or materialize real feature caches;
3. reproduce one reported metric point estimate;
4. run the first real clean-core pilot in non-claim mode;
5. inspect the first-benchmark undecided fraction;
6. only then decide whether to scale.

## What Would Justify V6

Only real-run failures justify V6, such as:

- provenance schema fails on real data;
- feature-cache schema mismatch;
- metric reproduction fails due to preprocessing details;
- certificate API fails on real stream scale;
- result-injection contract is too strict/loose;
- paper build or release scan fails;
- a claim gate fails to block unsupported evidence.

No generic polish V6.
